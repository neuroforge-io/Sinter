# Contributing to Sinter

Start with [development and tests](docs/DEVELOPMENT.md). Keep changes focused and
include regression coverage for failures as well as the successful workflow.
Use fictional or explicitly licensed fixtures, never private recordings, meeting
notes, credentials or proprietary ERAIS/Fracture implementation.

The core remains standard-library Python with browser-native assets. Propose new
runtime dependencies explicitly, including licence, distribution, privacy and
maintenance costs. Optional capabilities must remain optional.

Preserve original evidence and human corrections. Keep source material, deterministic
results and model suggestions distinguishable. Document admission/coverage limits,
data transfers, cancellation and recovery behavior. Do not silently replay a remote
mutation or weaken release checks merely to obtain a passing build.

Sinter is Apache-2.0; retain LICENSE, NOTICE and relevant third-party notices. Report
security-sensitive findings using [the security policy](SECURITY.md), not a public
issue containing private data or working credentials.
