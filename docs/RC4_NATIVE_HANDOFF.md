# Installed native owner and browser handoff

This is a separate Linux qualification route. It does not change the older
native-entry schemas, replace their four-process proof, or turn source/browser
tests into installed evidence. Unit receipts are synthetic parser controls.
An actual installed rehearsal and independent admission are still required.

The original four-path proposal over `b720b4a074b5d5d26b181e2db4f59d1c7a67b993`
and its independent refusal remain immutable. This corrected source proposal
uses `77ce8d7e6b2710fd2256795966abd3c032f11be8`, preserving all 441 files in that
checkpoint and owning only these four new paths. Earlier source test results are
historical, not results for this corrected source or the current installed app.

All work after the private Tk root is allocated is protected, including withdrawal.
Destruction is attempted even when withdrawal or a control fails. If both work
and destruction fail, the original exception stays selected and the destruction
exception is retained as its explicit cause in the child's complete stderr. A
failed child command is retained before parsing or status admission; failure can
never become a successful action. No additional Tcl or command input is exposed.

Within the fresh container, the continuing native owner and display are distinct
from each concurrent control and capture launcher. The launcher is also distinct
from the open-browser control that overlaps it. Sequential controls may reuse a
PID after the earlier child has exited. Host Node and the entire actual host
Chrome inventory must be disjoint; their PID numbers are never compared with a
different container namespace.

Launch, action, fixed-command and held-session evidence uses closed local fields
and builtin types. The held response is the complete source-defined `/api/session`
body, with the current version, workflows, owner notice/details, desktop owner
and local token. At this fixed phase the native No control has set quit state to
`cancelled`, while the held request and session observation are still admitted.
The later interrupted wire request must carry the same owner's token. `closed`
with active requests is refused. This replaces the earlier synthetic fixture's
two-field projection and unsupported `running` quit state; those old fixture
bytes stay retained. The new actual source HTTP control invokes the source
native-No method with an inert prompt, captures the real session and interrupted
response, and verifies cleanup without opening Tk, a browser or an installed app.

## What the operator runs

The owner first executes the unchanged V4 archive/native gate in its own fresh
container. That gate retains its four installed Tk processes, original command
order, exact package/menu/source identities, quiet post-reap native/display
streams, removal and complete container absence. Its receipt is independently
verified again by the new verifier. Failure stops the handoff route.

A second fresh container then explicitly installs the **same source-bound DEB**.
This separately recorded installation owns one continuing fifth native process,
an authenticated private Xvfb display, and the native process's loopback service.
The reviewed image is unchanged, network-none, and contains neither Git nor
Chromium. Host Git produces the real complete archive; verification re-archives
the actual repository. No caller origin or arbitrary command/Tcl API is exposed.

The fictional legacy and scoped-v2 projects retain full Unicode originals,
selected/empty/default-all question scopes, unknown permission, unassigned
ownership and an unconfirmed date. Installed JSON CLI operations seed a
source-only report containing a labelled historical human edit. They preserve
saved review/citation metadata and an explicit fictional custom-model selection.
The first typed SQLite/preferences snapshot is taken before native startup.

The UI-only driver enters unsaved native Unicode fields, selects the scoped
project in the real catalogue, confirms replacement, and observes the native
reader's refusal. The original unsaved fields and every persisted original stay
intact. It uses **Open full workbench** and the actual **No** save choice. The
native launcher's original loopback URL identifies its continuing owner PID.

One fixed host Chromium uses a fresh private profile, no inherited accounts and
an owned loopback debugger/relay. It inspects all three originals and the visible
question-scope controls. It edits a browser title without saving, then exercises:

1. **Keep working**: no quit POST.
2. A deliberately lost acknowledgement from one real quit POST: the native
   confirmation chooses **No**; browser inputs stay intact. The attempt remains
   **uncertain** and is never automatically replayed.
3. An admitted empty TCP connection: native close enters draining;
   **Keep window open** cancels it with both views intact.
4. Another explicit close while that same connection remains admitted: the
   unchanged real five-second product deadline refuses close and preserves work.
5. Explicit release of the controlled connection, followed by one incomplete
   JSON request: the real server returns interrupted-body HTTP 400 and leaves
   the workspace intact. No request replay occurs.
6. A final explicit browser quit POST and native **Yes / No save** choices:
   the complete successful acknowledgement and visible requested notice are
   retained before that browser context is closed to stop background polling;
   the same owner, listener and window finish normally. Unsaved drafts are
   deliberately discarded; they are not claimed to recover after that choice.

The transport conditions are labelled fixtures, not model/service outages.
The test does not claim to demonstrate arbitrary job cancellation, model quality,
physical menu activation, live accounts, upgrades or other operating systems.

The browser profile remains in the owned evidence tree. Its temporary files use
a separate exclusive `0700` directory in the fixed canonical `/tmp` namespace,
with a 55-byte UTF-8 path budget checked before any installed resource is acquired.
Long or Unicode evidence paths therefore do not lengthen Chromium's Unix socket.
The v3 browser receipt binds that directory's device, inode, permissions and
executor ownership before and after use, and requires complete removal. Existing
evidence-tree entry rules, native process checks and input conservation stay intact.

Chromium must expose its actual loopback debugger before Playwright starts. An
early browser abort retains its original PID, exit and complete output streams,
then attempts every owned cleanup. It does not start an unnecessary driver or
suppress startup/cleanup diagnostics. An aborted rehearsal remains failed; old
v2 receipts do not qualify under the new source and contract. Focused source or
cached-browser startup tests do not establish installed handoff acceptance.

## Running and checking exact identities

Only use a new private output root outside the repository and candidate inputs.
Pin the existing V4 owner, both new tool files, the host Chromium executable,
the actual Git commit and the package receipt. For a development rehearsal:

```text
python -B tools/rc4_native_handoff.py run
  --qualification dev
  --repository /absolute/clean/repository --source-commit EXACT_COMMIT
  --installer /absolute/candidate/Sinter.deb
  --package-receipt /absolute/candidate/package-test.json
  --output /absolute/private/new-output
  --owner-sha256 REVIEWED_V4_OWNER_SHA256
  --producer-sha256 REVIEWED_HANDOFF_PRODUCER_SHA256
  --contract-sha256 REVIEWED_HANDOFF_CONTRACT_SHA256
  --chromium /home/lloyd/.cache/ms-playwright/chromium-1234/chrome-linux64/chrome
  --chromium-sha256 REVIEWED_CHROMIUM_SHA256
```

The layout above is explanatory; combine the lines into one command when running
it. `--qualification candidate` admits only source version `0.5.4rc4` and still
requires the exact final source/tool/package identity. A DEV admission cannot be
relabelled as candidate evidence. The fixed Chromium path is a qualification
dependency, not a customer installation requirement. Missing image, interpreter,
browser security support or package bytes refuse qualification; the tool does
not download substitutes or ask anyone to disable OS security.

The standalone verifier takes the same `--qualification`, `--repository`,
`--source-commit`, `--installer`, `--package-receipt`, `--output`,
`--owner-sha256` and `--chromium-sha256` values. A pass requires both raw seven-role
container lifecycles, the old admission, typed raw seed/preservation snapshots,
original CLI/driver responses and requests, exact selected IDs, real scoped
browser response/capability, counted quit attempts, visible PNGs, measured
deadline and original interrupted response. HTTP 200 alone is insufficient.

All owned processes, process groups, native windows, display authorization,
listener/debugger/relay sockets, package paths and both containers must be gone.
Native, display, Tk driver and Docker streams are observed after reap; complete
host Chromium diagnostics are retained separately. Informational Chromium
diagnostics are not falsely described as quiet. Primary work errors survive
secondary cleanup failures; every independent resource gets its cleanup attempt,
and failed/partial evidence stays retained without admission.

Owner identity combines the actual container ID and its process PID. The old
baseline still requires its four distinct PIDs in its own namespace; a matching
integer in a separately admitted new container does not make it the same owner.

The proof/source/candidate/raw inventories are closed, including parent
directories. Unlisted files, empty directories, symlinks, sockets, FIFOs and
devices are refused before any read. Private Git, runtime and browser profile
internals have bounded variable inventories and still admit only real
directories and regular files; their contents are not application evidence.
The Playwright driver uses the same private no-account environment as Chromium.
Its actual binary/PID ownership and disappearance are retained. Its managed
IPC stdout is not claimed as a quiet or fully collected application stream.

The immutable image/client, local Docker daemon and installed host Playwright
dependency are trusted qualification infrastructure. The source/DEB/archive,
fixed flags, mounts and full byte hashes are checked; this is not a general
Docker API or a defense against a compromised host/daemon. Sinter remains a
local-first, single-trusted-user workbench. This route performs no model calls,
grant submission, email or account sign-in.
