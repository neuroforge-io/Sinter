# Owned RC4 installed offline workflow

This owner supplies a route to execute the existing fictional garden workflow
against a final installed Linux RC4 package. It does not change the UI journey,
old qualification defaults, schemas or prior evidence. Its source controls and
any source rehearsal do not establish an installed pass or authorise publication.

The route requires the exact committed `0.5.4rc4` source, a reviewed owner hash,
the corresponding DEB and same-build package test receipt, the already-qualified
local image, a selected Chromium executable and the separately qualified host
Python/Playwright runtime. There is no DEV promotion, image download, account
profile, hosted model request or automatic replay. The controlled container has
network disabled and loopback only, all capabilities dropped and no privilege
escalation. It is disjoint from the user workspace and all original inputs.

The container's root PID 1 owns installation and normal package removal. A fixed
`docker exec --user` controller uses the observed host UID and GID to own two app
lifetimes and the `/proof` fictional workspace. There is no ownership rewrite.
The host collector explicitly supplies the accepted `OwnedBrowserSession` to
the unchanged browser body and owns a separate private headless Chromium with
complete diagnostic streams. Managed Node uses Playwright's protocol transport;
its executable identity, command line and disappearance are recorded. Protocol
stdout is not presented as captured application diagnostics.

The journey verifies opening the example, inspecting sources, preparing a
handover, editing an action, saving, closing, restarting, exporting, restoring,
changed sources, stale reviews, conflicting saves and uncertain activity. The
contract admits the exact source-declared **53-entry legacy, 54-entry
funding-enabled or 55-entry focused-copy operation catalogue**, **22 named
checks** and **13 retained roles**, including the original handover and three
additional Word copies. The returned evidence records the actual catalogue count
from the fixed trusted source parser. It does not claim that every catalogue operation was
individually executed. Historical evidence remains historical.

Current candidate source declares 55 operations. Its funding summary and focused
copy must match their exact local operation IDs, routes and effects; a count
alone does not admit an arbitrary extension. This source catalogue does not
establish an installed pass or change any prior preview's catalogue.

The Word-copy exercise deliberately leaves changed report wording unsaved in
Sinter while preserving the original saved report. Saving a Word copy is a
separate local file operation. Before the final quit, the browser operator must
answer the current source's exact **Quit Sinter?** on-page decision, including
its warning and **Keep working** alternative. Historical previews retain their
browser-native decision handler. Missing or ambiguous source controls refuse;
there is no generic on-page-dialog acceptance. Consent alone cannot qualify a
quit: the original controller must observe exit 0 and the closed listener.

## Producer and original-tree review

Run from the final committed source using a new, short private home directory:

```console
python -B tools/rc4_installed_workflow.py run \
  --repository /absolute/committed/repository \
  --source-commit FULL_FINAL_COMMIT \
  --installer /absolute/Sinter-0.5.4rc4-linux-x64.deb \
  --package-receipt /absolute/Sinter-0.5.4rc4-linux-x64-test.json \
  --owner-sha256 REVIEWED_OWNER_SHA256 \
  --chromium /absolute/qualified/chromium \
  --output /home/user/short-fresh-proof
```

The final package/source must be prepared independently with the release
machinery. This owner never builds or downloads them. The output parent must be
owned and private, the output absent, and its `t` path at most 55 bytes long.
Use the separately reviewed host-tool observation wrapper to retain its actual
before/after fingerprints; this owner does not substitute a second host-tool
schema or imply that its internal observations satisfy that separate gate.

Original-environment review is read-only with respect to the application:

```python
from pathlib import Path
from types import SimpleNamespace
from tools.rc4_installed_workflow_contract import verify_original

result = verify_original(SimpleNamespace(
    proof_root=Path("/absolute/original-proof"),
    source_commit="FULL_FINAL_COMMIT",
    owner_sha256="REVIEWED_OWNER_SHA256",
    installer_sha256="FINAL_DEB_SHA256",
    package_receipt_sha256="SAME_BUILD_RECEIPT_SHA256",
))
```

It rechecks original raw command observations, complete streams, exact source,
package and binary bytes, owned cleanup, removal and absence, then invokes the
existing installed workflow semantic validator unchanged. Source archive
commands retain argv and post-reap ownership. Independent release authorization
must also compare the archive with the final Git object. The return schema is
`sinter-owned-rc4-installed-workflow-admission/v1`, with exact source/version,
installer/receipt/binary hashes, container identity and catalogue/check/role
counts. `release_qualified`, `cold_python_free_install` and
`historical_semantic_replay` remain false.

## Retained evidence and failure

The fresh original proof tree contains:

| Original role | Contents |
| --- | --- |
| `source/` | Complete committed QA bytes, conserved before and after |
| `repository/` | Exact Git tar and source ZIP |
| `candidate/` | DEB, same-build test receipt and fixed `workflow-input.json` |
| `raw/` | Git/Docker/controller/collector full streams and Git command records |
| `out/evidence/` | Installation controls, payload, frozen diagnostics, self-test, catalogue, removal and independent path absence |
| `out/workflow/` | Unfinished and completed generic receipts plus the unchanged 13 retained UI roles |
| `out/host.json`, `out/chrome/` | Owned browser/driver/relay observations and complete Chromium streams |
| `runtime/` | Two app lifetimes, original app streams, controller, ready/stop/removal states and fictional workspace |
| `workflow-owner.json` | Outer command ownership, cleanup attempts, source and tool observations |

Every independent cleanup is attempted even after an earlier fault. The first
actual exception is preserved, all cleanup failures and parallel owner failures
remain recorded, and stream capture never converts failure into success. Forced
container/process removal cannot qualify. Known browser temporary entries are
inventoried and cleaned only after the host collector has reaped; their original
observations remain retained. Unknown, linked, special, deep or oversized entries
refuse admission under the existing finite limits. Failed temporary receipt
delivery preserves its `.pending` bytes.

Return code 0 means this particular original-tree workflow gate completed.
Return code 1 means refusal/failure; interruption may retain a nonzero signal
status. No request is automatically replayed. Retain the failed tree and use a
new explicitly selected output for another run. A completed generic receipt
alone is insufficient without this outer ownership review.

## Required separate release gates

The qualification image contains Python and controller tools. This adapter
does **not** prove that a customer can install and run without Python. A separate
actual account-free, network-disabled, Python-free cold-install/uninstall gate
is required, alongside the final binary's native ownership, recovery, prior
preview replacement, raw notices, host-tool fingerprints and source/package
bindings. No other platform is qualified by this route.

A public portable historical semantic verifier is not claimed. A narrower
release may retain this immutable original evidence and its exact original
admission, then ship the independently reviewed integrity/transport catalogue
with `historical_semantic_replay: false`. Public integrity checks establish byte
integrity and inventory, not a fresh installed test. Original evidence must not
be rewritten or replaced with admission booleans. Shipping still requires the
actual final package, actual gate execution and independent final review.

The workflow owner must be prepared and run as an observed nonzero UID. The
producer refuses UID 0 before observing source/browser identities or creating
its preparation tree, and the closed input contract refuses UID 0 before forming
controller arguments. The existing numeric GID policy and the separate root
package-install owner are unchanged.

Preparation command receipts and the final qualification receipt keep their
original successful JSON bytes and schemas. If a body fails and its receipt is
saved, the identical original exception still propagates. If saving that receipt
also fails, the source-fixed writer records every publication failure and keeps
the complete intended bytes, counts and hashes in a typed failure, with the
original exception object as its cause. The independently attempted fallback is
named after the original receipt with `.failed.json` appended; it is diagnostic
material and cannot qualify a run. Failed `.pending` files remain original
partial evidence. A failed or uncertain command is never replayed automatically.

The shared, independently reviewed failure publisher and safe CLI emitter are
explicit source dependencies. Only the two receipt boundaries use the workflow
writer callback. Compound write/close exceptions are observed within that exact
writer activation; no global tracing or receipt-selected code is used. Surrogate
filesystem names receive reversible JSON escapes in diagnostic bytes while
valid Unicode successful bytes remain unchanged. All command/app/browser
streams, cleanup attempts and installed semantics retain their existing bodies.
These source regression controls establish fault handling only; the final
installed journey and separate Python-free cold-install gate remain required.
