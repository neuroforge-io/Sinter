# Installed Linux recovery rehearsal

This separate route runs both mandatory fictional recoveries against one actual installed Linux executable: six campaign lifetimes, then four scoped-project lifetimes. It does not admit a release, a prior replacement, a native owner transition, a physical menu click or another platform. Historical RC3/source receipts, defaults and admission maps remain unchanged.

The `run` command owns a fresh restricted container from the already retained image. It installs the supplied DEB inside that container, binds the complete candidate Git archive and package receipt, checks actual package status, executable and both menu-entry bytes, and compares actual frozen diagnostics/self-test with the package receipt. It removes only its own package/container. It never builds, downloads or substitutes an image and never installs on the host.

Host Playwright uses private headless Chromium through the existing owned loopback/UNIX relay. The fixed image contains no Chromium or Playwright. A fixed `BROWSER` helper captures the app's request; this does not prove an OS browser accepts it. Each app command is exactly `/opt/neuroforge/sinter/Sinter app --mode browser --directory OWNED_DATA`.

Run from the exact reviewed QA source with unoptimised Python, Linux and an owned home temporary directory. Use a fresh private output parent; the owned output plus `/t` must be at most 55 UTF-8 bytes, keeping Chromium socket paths within their platform limit. Select an existing headless launch file explicitly; its hash is retained before and after the run. This binds the selected launch file, not all host browser dependencies. A future operator supplies the exact reviewed source commit, DEB and same-build package receipt:

```text
python -B tools/rc4_installed_recovery.py run \
  --boundary development \
  --repository /owned/exact-repository \
  --source-commit FULL_COMMIT \
  --installer /owned/candidate/Sinter-VERSION-linux-x64.deb \
  --package-receipt /owned/candidate/Sinter-VERSION-linux-x64-test.json \
  --owner-sha256 REVIEWED_PRODUCER_SHA256 \
  --output /owned/private/fresh-proof \
  --chromium /existing/host/chromium
```

`development` permits only `0.5.4rc4.dev0`, explicitly binds a separate reviewed QA origin and requires every production source byte to match the candidate archive. It is a prototype rehearsal, never tag admission. `candidate` requires `0.5.4rc4` and one complete exact identity for all candidate and QA files. It still does not qualify a release. There is no profile skip, source-fixture substitution or historical-receipt promotion.

The optional shared UI observer and `browser_session` arguments preserve their existing omitted defaults. The installed caller maps only the current campaign/scoped workspace to fixed read-only operations. Records bind session, profile, monotonic sequence and operation, retain complete request/response bytes on both sides, refuse unknown fields/paths/SQL/commands, and have finite byte/count/time bounds. The host-private ancestor remains mode0700; only fresh fictional control/exchange subdirectories are writable. No chown, setuid, added capabilities or fake host database reads are used.

The inner owner observes live SQLite schema, typed rows, user_version/application_id/encoding/page_size and full preference bytes before each app/CLI reopen. Changed seeded originals/settings refuse without migration or repair. Actual scoped CLI get/validate/build/full export each follows its own raw before-reader guard and compares the entire typed snapshot immediately after reap. If one changes records, no later reader is started. Complete CLI inputs, outputs, errors and partial command observations are retained on failure. The scoped browser also executes the thirty missing/wrong/duplicate capability cases before queued work. Source NativeController probes are not installed native proof; that separate installed owner/refusal gate remains required.

Both journeys retain full original inputs, raw report identity/history, quoted source ranges, unknown/unassigned owners, unconfirmed dates, review meanings, complete clipboard/manual backups and separate restore identities. Campaign controls retain conflicts, stale source checks, actual committed save with a synthetic lost reply, uncertain quit, Keep working and explicit restart without automatic replay. Scoped controls retain stale question choices, visible warnings, source-only handover, applied partial human wording, actual Word parts, action edit and real stops/reopens.

Fictional seed preparation uses the exact candidate production source and creates only disabled watches. The actual frozen scheduler/provider code is not monkeypatched. Network-none and empty fictional homes prevent remote/account access. The relay measures model-route requests; internal provider attempts remain **unmeasured** and are never reported as zero. Transport reply loss, clipboard denial, seed preparation and browser capture are disclosed instrumentation.

The inner relay tracks accepted sockets through request-worker completion and requires supervisor, request and socket cleanup. The host collector has its own actual PID, complete argv and post-reap streams. Streams are retained after reap, with full count/hash and bounded reversible samples. Unknown callback diagnostics, truncation, forced cleanup, surviving process groups/ports, observation loss and incomplete profiles refuse. Package removal accepts empty stderr or only the exact separately reviewed `/opt`-not-empty notice, while independently requiring absence of the executable and both Sinter entries; it never hides that notice or broadly ignores dpkg warnings.

This proposal's finite tests exercise source/IPC/process mechanics only. No installed rehearsal, binary invocation, package installation, image execution or release qualification has yet been run by this proposal author. The parent must execute the immutable reviewed route against its exact candidate, retain actual failures, and obtain independent artifact review. Published E replacement, matching recovery/native/workflow evidence and final canonical admission remain separate unresolved release gates.

For independent read-only artifact review, use the same exact reviewed QA source:

```text
python -B tools/rc4_installed_recovery.py verify \
  --proof-root /owned/private/completed-proof \
  --owner-sha256 REVIEWED_PRODUCER_SHA256 \
  --source-commit FULL_CANDIDATE_COMMIT \
  --installer-sha256 REVIEWED_DEB_SHA256 \
  --package-receipt-sha256 REVIEWED_PACKAGE_RECEIPT_SHA256
```

`verify` launches no container, app, browser or network request. It checks the retained seven raw owner roles, complete package/process/UI/RPC artifacts and explicit external pins. A source-worker receipt, an incomplete or relabelled source folder, missing frozen evidence, changed inputs, foreign artifacts, wrong types or partial profiles cannot satisfy this new installed contract. A successful verification remains a bounded installed-recovery rehearsal; release, native-owner and prior-replacement flags remain false.

The provided `OwnedBrowserSession(phase)` is callable as a context manager and returns the normal Playwright driver. Its `launch(driver, chromium)` returns a delegated browser/context API; `observations()` retains closure flags and every cleanup attempt/error. UI/body failures stay primary. Context, browser, driver, relay and final observation cleanup are attempted independently. Cleanup-only failures remain failures. Failed host responses and aggregate resources are retained; if an evidence write itself fails, that failure is reported and cannot qualify. Atomic response writes retain unpublished temporary bytes rather than inventing a delivered acknowledgement.

The complete extracted installer TAR stdout and stderr are retained in fixed sidecars and matched to the actual command record before deriving binary/menu identities. Exact control-query output, package-receipt bytes and independent filesystem-query output are also bound. Required screenshots must be bounded valid PNG pixels; their warning wording and input visibility still need review of the actual screenshot and measured browser controls. A PNG parse alone proves neither usability nor visible semantics.

The earlier `06b994a0…`, `f25d5c68…` and final-v2 proposals, their positive source checks and independent refusals remain immutable. This new seven-path repair is composed over `77ce8d7e6b2710fd2256795966abd3c032f11be8`, including its separately accepted workflow browser-session seam. All 438 non-owned base files are preserved. Earlier b720 execution is not relabelled as current-source evidence. New evidence remains source/IPC mechanics until the parent executes an independently reviewed installed route.

After complete collector reap and stream retention, only the fixed fresh owned `/t` cache is eligible for cleanup. The current selected Chrome leaves an observed `com.google.Chrome.chrome_chrome_url_fetcher_.XXXXXX` directory with one fixed known cache filename. The owner inventories every path/type/size/hash before deletion, rejects unknown names, links, special entries or more than 64 entries, bounds each cache file to 32 KiB, records every removal outcome and retains all failures. It deletes no proof, diagnostic, workspace or exported document. Browser close success alone is not evidence that temporary cache files disappeared. Other unreviewed browser cache shapes refuse rather than broadening this policy.

The host collector requires an empty temporary directory before starting and checks browser identity after its profiles finish. It leaves cache files for the outer owner's post-reap inventory and cleanup; the host does not claim final cache emptiness before it exits. Final verification still requires the independently recorded completed cleanup and empty fixed temporary directory.

Removal must pass the unchanged shared strict stopped-process predicate and match exactly one actual `dpkg -r sinter` entry in the inner command inventory. The complete process identity and streams cannot be substituted by a separate summary. The exact warning policy and independent package/path absence checks remain mandatory.

Each profile inventory enumerates files and directories with a 512-entry and eight-component depth bound, while retaining the existing per-file and total byte limits. Every directory must be a parent of a returned file; unlisted empty directories, links and special entries refuse. The caller then requires the exact fixed profile file roles, so unknown nonempty directories cannot smuggle extra file roles into admission.

The intermediate `f25d5c68…` freeze also remains unchanged: its source journeys passed, but a separate inert witness showed that its profile inventory ignored an unlisted FIFO. The revised inventory refuses special entries without reading them. The installed filesystem probe now requires its exact source-fixed original stdout bytes, including duplicate/extra-byte refusals. Driver-start failure also attempts manager cleanup while preserving the start failure.
