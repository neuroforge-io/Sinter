# Handover reading qualification — 20 October 2026

This is a development-source qualification of the optional **Write handover
opening** workflow. It is not an installed release or a whole-product quality
score. The source change is based on main `33366aac10a1e879d0921c4c0b1606968e861f08`;
the integration commit must contain the source blobs listed below.

## Result and retained evidence

New openings are ordinary item headings followed by labelled paragraphs, in the
same order in the app, editable Markdown and Word: proposed next step, Evidence,
recorded status, wording period, responsibility and timing. Long status text no
longer pushes the first evidence control below the demonstrated phone viewport.
The original checklist, source identities, selected quotations, reference ranges
and review state remain attached. Unknown and unassigned owners remain distinct;
a role is not an accepted person, and a proposed target is not a funder deadline.

Earlier saved table openings retain their legacy presentation. The frozen
pre-recipient oracle is unchanged. A separate frozen table fixture was generated
with the actual parent compiler and independently matched at 835 bytes and
SHA-256 `7c103544c65550421cad47497fc8620cafd4b5033112d551b25c7c6284776c91`.

The new browser and Word presentation adapters admit the complete optional opening
before styling it.
Human edits or ambiguous shapes retain generic document rendering. Styling is
not evidence verification. Canonical escaping, literal spacing and Unicode are
preserved; repeated Passage selections remain associated with their item.
Word links use the existing admitted original Passage/reference destinations.

The independent source critic found and prompted regressions for BOM-only blank
fields, empty selected quotations, false table guidance from quoted headers, and
a bounded long quotation containing 150,000 separate backtick runs. The fixes
preserve legacy defaults and avoid an argument-count exception during reading.
